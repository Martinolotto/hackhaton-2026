# Rule: Dashboard / Admin Panel Layout

## Rol

Optimiza tareas repetidas, monitoreo y administración mediante navegación estable, densidad calibrada y jerarquía de datos.

## Estructura

- Separar navegación global, contexto de página, controles, contenido y feedback.
- Métricas principales deben responder preguntas concretas.
- Tablas son preferibles a cards cuando comparar filas sea central.
- Filtros muestran estado, alcance y forma de restablecer.
- Acciones peligrosas se separan y confirman proporcionalmente al riesgo.

## Responsive

- Priorizar tareas; no intentar conservar todo el dashboard.
- Tablas pueden usar scroll horizontal controlado, columnas prioritarias o vistas por fila.
- Sidebar puede colapsar conservando ubicación y labels.
- Mantener acciones esenciales accesibles con teclado y touch.

## Estados

- Diseñar loading, partial loading, empty, no-results, stale, error y permisos insuficientes.
- Mostrar fecha/rango/unidad de cada métrica.
- Preservar filtros y paginación cuando sea útil.

## No debe

- Llenar la cabecera con métricas decorativas.
- Usar gráficos sin escala, unidad o alternativa textual.
- Ocultar acciones tras hover.
- Confundir color de marca con severidad.

## Formato de salida

Definir regiones, densidad, jerarquía de métricas, comportamiento de tablas/filtros y adaptación móvil.
